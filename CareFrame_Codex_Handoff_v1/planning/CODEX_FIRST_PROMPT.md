# Codex 첫 메시지 — 그대로 전달

우리는 1인 팀이며 7시간 해커톤에서 수상을 목표로 한다.
지금부터 새로운 제품을 기획하지 말고 아래 범위를 구현하라.

제품은 "영희 — 우리집 AI 건강 길잡이"다.
의료 지식이 없는 성인이 상복부 불편감을 음성으로 설명하면,
가상의 AI 대화 상대 영희가 필요한 내용을 확인하고,
설정한 위험 신호에서는 일반 문진을 중단하며,
끝에는 환자 진술과 미확인 항목이 구분된 문진표를 인쇄한다.

먼저 AGENTS.md와 planning/START_HERE.md,
planning/PRODUCT_AND_TECH_SPEC.md, planning/BUILD_AND_DEMO.md를 읽어라.
문진 구현 전 DATA_CONTRACTS.md, CLINICAL_PROTOCOL.md, ACCEPTANCE_TESTS.md를 읽어라.
모델·SDK에 대한 현재 공식 문서와 설치한 패키지 타입을 확인하되 탐색은 시간 제한을 지켜라.

고정 조건:
- Next.js App Router + TypeScript + 단일 저장소.
- 기본 음성 경로는 OpenAI Agents SDK의 RealtimeSession/WebRTC.
- 브라우저에는 단기 토큰만 제공하고 일반 API 키는 서버에 둔다.
- 자동 음성 응답을 끄고, 전사 완료 → 서버의 사실 추출/검증/규칙 처리
  → 승인된 다음 문장 순서로 동작하게 한다.
- Realtime 모델에 strict Structured Outputs 지원을 가정하지 않는다.
- 별도의 Responses API 구조화 출력은 사실 추출에만 사용한다.
- 모델이 다음 행동이나 임상 위험 등급을 자유롭게 결정하지 않게 한다.
- 문진표는 검증된 상태의 결정적 렌더링이다. 마지막에 LLM으로 다시 쓰지 않는다.
- 데이터베이스, 로그인, localStorage 기반 병력 저장, 여러 페르소나는 만들지 않는다.
- 상태는 브라우저 메모리, 임상 처리는 stateless 서버 요청으로 구현한다.
- 가상 증례 시연용 표시와 AI 고지는 항상 유지한다.
- 안전 판단을 완전히 보장한다고 주장하지 않는다.

첫 60분의 목표는 "한국어 음성 3턴 + 전사 이벤트 + 마이크 종료 + 자동응답 억제"의 실제 성공이다.
처음 15분에는 저장소/환경/모델 접근/배포를 확인하고 음성 연결을 시작하라.
60분 안에 성공하지 못하면 BUILD_AND_DEMO.md의 고정된 Plan B로 전환하라.
성공하지 않은 기능을 mock으로 감추지 말고 명확히 표시하라.

그 다음에는 한 번에 전체 앱을 생성하지 말고:
1. 타입·상태·텍스트 문진·규칙·문진표,
2. 음성 연결과 상태 통합,
3. 테스트와 오류 수정,
4. 녹화와 제출 준비
순서로 진행하라.

각 단계가 끝날 때 PROGRESS.md에
완료된 항목 / 실제 실행한 테스트 / 실패·미검증 / 다음 30분 작업
을 짧게 남겨라.
확인 가능한 작은 커밋을 만들고 이력을 재작성하지 마라.

작업을 막는 API 접근·권한 문제나 임상 문구 승인 필요만 질문하라.
색상·레이아웃·파일명 같은 가역적인 사항은 명세 기본값으로 진행하라.
새 기능 제안, 과도한 리팩터링, 여러 브랜치 병렬 개발은 하지 마라.
