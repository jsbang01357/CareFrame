목표: 20팀 중 상위 3위 도전.
이 문서의 시간 배분은 팀의 결정이다. 실제 순위를 예측하는 점수표가 아니다.

공식 페이지 기준 개발·제출 종료는 17:00, 1차 발표는 4분이다.
빈 저장소, Codex 사용 기록, 최종 커밋·PDF·데모 링크와 사전 작업 공개를 준비한다.
현장 최종 안내가 달라지면 그것을 따른다. [S1]

### Codex

화면/인쇄, 빌드/배포 문제 해결, 실제 실행 결과 정리.

### 지송님
문진 항목과 안전 문구 검토, 가상 환자 역할,
원문-문진표 수동 대조, 실제 음성 동작 확인,
사실에 맞는 발표 문구, 녹화·리허설·최종 제출.

임상적 판단 기준을 Codex의 자신감에 맡기지 않는다.
반대로 색상/레이아웃 등 가역적인 결정은 Codex에게 맡긴다.

## 3. 60분 음성 게이트
아래가 모두 성공해야 Plan A를 유지한다.
- 실제 브라우저 마이크로 한국어를 말한다.
- 답변 음성이 실제로 나온다.
- 확정 사용자 전사가 식별 가능한 ID와 함께 나온다.
- 자동 응답을 막고 승인 후에만 응답시킬 수 있다.
- 사용자가 말을 끊으면 출력이 중단된다.
- 종료 시 마이크가 해제된다.

연결 아이콘만 뜨거나 텍스트 입력만 되는 것은 통과가 아니다.

## 4. 고정 Plan B
60분 안에 위 조건이 안 되면 더 오래 SDK와 싸우지 않는다.
**녹음 완료 → 파일 전사 → 같은 /api/turn → 승인 텍스트 TTS**로 전환한다.

마이크는 버튼 방식이고, AI 질문은 실제 음성으로 재생한다.
독립적인 새 문진 엔진을 만들지 않는다.
추가 endpoint는 /api/transcribe와 /api/speak뿐이다.
공식 지원 녹음 형식과 브라우저 MIME을 확인하고, 음성 파일을 장기 보관하지 않는다.
실시간 자유대화가 아닌 턴 기반 음성 문진임을 발표에서 밝힌다.

Plan B에서도 원문·부정/미확인·안전 중단·인쇄는 유지한다.
Plan B까지 실패하면 텍스트가 실제 구현 범위다.
녹화로 존재하지 않는 음성 기능을 만들어 보이지 않는다.

## 6. 데모 이야기
가상 인물: 60대 성인. 이름·목소리는 연기이며 실제 환자가 아니다.

### A — 편하게 말하면 기록이 남는다
“영희야, 사흘 전부터 명치가 쓰리고 밥 먹으면 더 그래.”
한 발언에서 시작 시점·위치·양상이 채워진다.
영희는 이미 얻은 내용을 되묻지 않고 다음 중요한 질문을 한다.
마지막에 “약 이름은 잘 모르겠어요”를 남긴다.
리포트는 약 없음이 아니라 “약 정보 모름”으로 표시한다.

### B — 편안함보다 안전이 먼저다
“지금 명치랑 가슴이 꽉 눌리고 숨쉬기도 어려워. 식은땀도 나.”
일반 질문이 중단되고 긴급 안내가 뜬다.
“심근경색을 맞혔다”가 아니라 “사전 정의한 위험 신호에서 대화를 중단했다”고 설명한다.

## 7. 70초 영상 구성
| 길이 | 장면 |
|---|---|
| 0~12초 | AI 고지 후 영희와 실제 음성 대화 시작 |
| 12~30초 | 발언 한 번에서 여러 필드가 채워지는 모습 |
| 30~45초 | 원문 클릭, ‘약 모름’과 ‘미질문’ 구분, 출력 |
| 45~65초 | 별도 위험 사례, 일반 질문 중단과 고정 안내 |
| 65~70초 | 다음 행동 + 병원에 전달할 자료 |

긴 대화는 실제 원본에서 발췌한다. “중간 문진 생략”을 화면에 표시한다.
자막을 넣고, 전체 실제 녹화 파일도 보관한다.
녹화본은 그대로 재생하는 녹화본이다. 라이브인 척하지 않는다.
발표용 PDF에 영상이 자동 재생될 것이라고 가정하지 않는다.
운영진 재생 방식에 맞춰 MP4/재생 링크와 오프라인 대체 화면을 준비한다. [S1]

## 9. 발표 문장
### 도입
“집에서 아플 때, 우리는 어디로 가야 할지만 모르는 게 아닙니다.
무엇을 말해야 하는지도 모릅니다.
영희는 편하게 이야기를 듣고, 의료진에게 전달할 준비를 돕는 AI입니다.”

### 기술
“목소리를 내는 AI가 의료 판단까지 마음대로 하게 하지 않았습니다.
발언을 사실로 구조화한 뒤, 코드가 질문 순서와 중단을 결정합니다.
모르는 정보는 모른다고 남깁니다.”

### 검증
“오늘 [실제 실행한 수]개의 가상 사례에서 [실제 항목]을 확인했습니다.
[실제 발견한 오류]가 있었고 [실제 변경] 후 다시 실행했습니다.
이 결과는 임상 안전성이나 진료시간 단축을 입증한 것은 아닙니다.”

### 도입 가능성 — 매출 대신 실제 사용 장면
“병원 예약 링크나 지역사회 건강 안내에 연결하는 형태를 다음 가설로 생각합니다.
오늘은 가정에서의 음성 대화와 진료 정보 전달까지 구현했습니다.
실제 사용자와 의료진이 유용하게 느끼는지는 이후 확인해야 합니다.”

### 마무리
“편하게 말할 수 있게, 그리고 정확히 전달할 수 있게. 우리집 AI 건강 길잡이, 영희입니다.”

## 10. 결선 질문 대비
- 그냥 ChatGPT인가? → 음성은 AI, 정보 상태/질문/중단/리포트는 별도 코드. 실제 검증 결과를 보여준다.
- CPX로 응급도를 판정하나? → 아니며 문진 틀만 참고. 데모 안전 규칙도 임상 검증되지 않았음을 밝힌다.
- 음성 인식 오류는? → 자동 전사 표시, 원문 확인, 정정, 불확실성, 실제 음성 테스트. 완전 해결을 주장하지 않는다.
- 정말 시간 절약인가? → 아직 측정하지 않았다. 이번에 측정한 것은 정보 보존과 동작이다.
- 모든 가정에서 쓸 수 있나? → 현재는 단일 경로 가상 증례 데모다. 일반 임상 사용과 확대는 별도 과제다.
- 왜 페르소나인가? → 편하게 말하게 하는 UX 가설. 임상 기준은 캐릭터와 분리했다.
- 수익 모델은? → 이번 결과물은 사용성 검증 단계다. 의원/지역사회 배포 가설만 있으며 계약·매출은 없다.
