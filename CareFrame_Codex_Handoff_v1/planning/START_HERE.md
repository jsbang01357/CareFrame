# 영희 — 7시간 해커톤 인계 패키지
버전 1.0 · 기준일 2026-10-09 · 상태: 설계 완료 / 앱 구현·API 실호출·성능검증 전

## 최종 결정
- 제품: **영희 — 우리집 AI 건강 길잡이**
- 사용자 경험: 의료 지식이 없는 성인이 집에서 편하게 증상을 말하고, 다음 행동과 진료 준비 자료를 얻는다.
- 당일 구현: **영희 1명 × 성인 상복부 불편감 1개 문진 경로 × 음성 대화 × 위험 신호 중단 × 출처가 있는 문진표**.
- 진단·처방·자가검진·의료적 안전 보증은 제공하지 않는다. 시연은 가상 환자만 사용한다.
- 목표: 트랙 내 20팀 중 상위 3위 도전. 순위는 목표이지 보장이나 성능 지표가 아니다.
- 14:00 핵심 기능 동결, 16:40 제출 목표. 7시간 중 약 4시간을 제품에, 나머지를 검증·데모·제출에 사용한다.

## Codex에 넘기는 순서
1. 행사에서 요구하는 빈 저장소 등록을 먼저 끝낸다.
2. 이 자료를 `planning/`에 넣고 기획·설계 보조 자료임을 공개한다. `AGENTS.md`는 루트에 놓는다.
3. `CODEX_FIRST_PROMPT.md`를 첫 메시지로 전달한다.
4. Codex는 먼저 이 파일, `PRODUCT_AND_TECH_SPEC.md`, `BUILD_AND_DEMO.md`를 읽는다.
5. 문진 엔진 구현 전에 `CLINICAL_PROTOCOL.md`, `DATA_CONTRACTS.md`, `ACCEPTANCE_TESTS.md`를 읽는다.
6. 실행 코드, 타입/설정 파일, 테스트 구현은 Codex에서 작성한다.

외부 AI를 이용한 설계 지원도 Only Codex 규정에 포함되는지 운영진에게 확인한다.
이 문서는 기획자료일 뿐, 행사에서 자동으로 허용되는 예외를 의미하지 않는다.
실제 의료문진 프로토콜과 안전 문구는 지송님이 검토하고, 검토 완료/미완료 상태를 기록한다.

## 제출 전에 남아 있으면 안 되는 결함
- 사용자가 말하지 않은 부정 소견을 문진표에 기록한다.
- 위험 신호 처리 중 음성 에이전트가 먼저 안심시킨다.
- 약 이름을 모르는데 특정 약이나 약물군으로 단정한다.
- 보호자·과거 병력을 현재 환자 증상으로 옮긴다.
- 실패한 API 호출을 성공한 데모 화면으로 대체한다.
- 테스트를 실행하지 않았는데 통과했다고 표시한다.
