# 상복부 불편감: 자체 작성 데모 문진 프로토콜
ID: upper-abdomen-demo-1
상태: **임상 검토 미완료. 가상 증례 시연 전용.**
검토자 / 검토 시각 / 승인 버전: 구현 시 실제 값을 작성한다.

이 문서는 CPX식 병력 수집을 참고한 자체 설계다.
공식 CPX 54증례 목록, 공식 국시 채점표, 검증된 triage 지침을 제공받아 재현한 문서가 아니다.
따라서 “54증례 임상 검증 완료” 또는 “국가시험으로 검증된 AI”라고 표현하지 않는다.
공개 참고자료 [S9, S10]은 위험 신호의 예를 뒷받침할 뿐, 아래 알고리즘 전체를 검증하지 않는다.

## 1. 지원 범위
성인이 자신의 명치/상복부 통증, 쓰림, 불편감을 설명하는 상황.
초기 대화에서 다른 부위·다른 문제라고 드러나면 억지로 복통으로 분류하지 않는다.
소아, 임신 관련 문제, 정신건강 위기, 복합 문제의 독립 경로는 오늘 구현하지 않는다.
지원 범위 밖이어도 분명한 현재 위험 신호가 있으면 범위 안내보다 도움 요청 안내가 먼저다.

## 2. 필드 사전
### 기본 문진
| field_id | 내용 | 자연어 질문의 예 |
|---|---|---|
| chief_complaint | 주호소 | 오늘 어디가 가장 불편하세요? |
| location | 위치 | 가장 불편한 곳을 손으로 짚는다면 어디인가요? |
| onset | 시작 시점 | 언제부터 불편하셨나요? |
| pattern | 지속/반복 양상 | 계속 불편한가요, 아니면 괜찮아졌다 다시 불편해지나요? |
| severity_function | 강도/기능 영향 | 지금 불편함이 일상생활을 얼마나 방해하나요? |
| medications | 현재 복용약 | 요즘 드시는 약이 있나요? 이름을 모르셔도 괜찮아요. |
| concern | 가장 걱정되는 점 | 이 증상 때문에 특히 걱정되는 점이 있으세요? |

### 우선 확인할 위험 관련 항목
| field_id | 확인 내용 |
|---|---|
| rf_chest_discomfort | 현재 가슴의 통증·압박감 |
| rf_breathing_difficulty | 지금 새롭게 발생했거나 악화된 숨쉬기 어려움 |
| rf_fainting | 이번 증상 중 실신·쓰러짐 |
| rf_sudden_or_severe_abdominal_pain | 매우 갑작스럽거나 심한 복통 |
| rf_vomiting_blood | 이번 증상 중 피/커피 찌꺼기 양상의 구토 |
| rf_black_tarry_stool | 이번 증상 중 검고 끈적한 변/의심되는 출혈 |

### 자발적으로 말하면 기록할 항목
character, meal_relation, vomiting, fever, cold_sweat,
medical_history, weight_change, patient_belief.
이들은 기본 질문 목록을 무한히 늘리는 이유가 아니다.
관련 진술이 나왔는데 중요성이 애매하면 범위와 불확실성을 표시한다.

‘검은 변’을 약 복용 때문이라고 AI가 단정해서 지우지 않는다.
‘진통제’라는 단어만으로 NSAID라고 바꾸지 않는다.
‘속이 답답함’을 자동으로 흉통이나 소화불량 진단으로 바꾸지 않는다.

## 3. 질문 정책
순서:
1. 이미 분명하게 말한 위험 신호를 즉시 처리한다.
2. 문진 대상·범위가 불명확하면 짧게 확인한다.
3. 미확인 위험 관련 항목을 한 항목씩 묻는다.
4. 기본 문진 중 아직 수집되지 않은 항목을 묻는다.
5. 사용자가 가장 걱정하는 점을 듣고, 수집된 내용을 확인받는다.

한 번의 사용자 발언에서 여러 필드를 얻을 수 있다.
하지만 “전부 없죠?” 같은 한꺼번의 부정 확인은 하지 않는다.
“아니요”는 바로 연결된 질문에만 적용한다.

같은 항목을 재확인하는 것은 unclear/전사 정정일 때만 허용한다.
이 경우 1회 재질문 뒤에도 불명확하면 미확인으로 남긴다.
위험 정보를 충분히 확인하지 못하면 완료 또는 비응급으로 표시하지 않는다.

일반 답변 상한은 12턴이다.
상한 때문에 필수 질문이 남았으면 partial report로 전환한다.
자연스럽게 많은 정보가 나온 경우 더 짧게 마칠 수 있다.
문진 길이를 맞추기 위해 질문을 생략한 뒤 “충분히 확인함”이라고 표시하지 않는다.

## 4. 안전 규칙 — 데모용, 완전한 의학적 분류 아님
### R1: 현재 위험 신호가 명확함
현재 본인의 위험 항목이 reported이고 문맥상 현재 사건임이 확인되면 긴급 경로로 전환한다.
각 신호의 의미·현재성은 지송님이 검토한 테스트 예문에 따라 확인한다.
예: 명치 불편감에 현재 가슴 압박감과 새 호흡곤란이 함께 명시됨.
예: 피를 토했다는 명확한 현재 진술.
예: 갑작스럽고 심한 현재 복통.

어떤 병인지 맞히려 하지 않는다.
심근경색, 위궤양, 위장염 등의 진단명이나 발생 확률을 생성하지 않는다.
NHS의 복통 안내와 질병관리청의 심근경색 안내는 급성 위험 신호와 즉각적 도움 요청의 참고자료다. [S9, S10]

### R2: 애매한 위험 신호
“검었던 것 같아요”, “숨이 찬 건지 잘 모르겠어요”는 denied가 아니다.
짧은 확인 질문 1회 후에도 불명확하면 pending_clarification으로 남긴다.
“안전”이나 “응급 아님” 대신 평가 한계를 밝히고 의료기관에 문의하도록 안내한다.
분명한 다른 긴급 신호가 있다면 이 확인 질문을 기다리지 않는다.

### R3: 다른 사람/과거 이야기
“아버지가 작년에 심근경색으로 쓰러졌어요”를 사용자의 현재 실신으로 기록하지 않는다.
현재 다른 사람이 쓰러졌다는 이야기라면 일반적 긴급 도움 요청을 우선할 수 있지만,
본인 문진의 임상 사실에 병합하지 않는다.

### R4: 단순 키워드 차단 금지
단어 출현만으로 “호흡곤란 없음”을 호흡곤란 양성으로 만들면 안 된다.
부정·현재/과거·본인/타인을 같이 처리한다.
음성 인식 오류와 LLM 추출 오류가 남으므로 deterministic rule도 임상 안전 보증이 아니다.

## 5. 사용자에게 보여줄 행동
### urgent_help
“말씀하신 내용에는 지금 바로 의료진의 평가가 필요한 위험 신호가 있습니다.
문진을 계속하기보다 119에 연락해 도움을 요청하세요. 직접 운전하지 마세요.”
고정 안내의 최종 문구는 사용자 검토 후 기록한다.
실제 전화 연결/신고 완료를 자동으로 표시하지 않는다.

### 일반 진료 준비
“말씀하신 내용을 진료 때 보여드릴 수 있게 정리했어요.
증상이 지속되거나 반복되면 가까운 내과·가정의학과 등 의료기관에 문의해 진료를 받으세요.
이 대화만으로 응급질환을 배제할 수는 없어요.”
구체적인 ‘며칠은 기다려도 안전하다’는 기간을 자동으로 정하지 않는다.
일반 경로를 ‘녹색 안전 판정’으로 표현하지 않는다.

### 불완전/범위 밖
“현재 준비된 문진 범위나 확인된 정보만으로는 다음 행동을 충분히 판단하기 어렵습니다.
확인한 내용만 정리하고, 의료기관에 문의해 안내받으세요.
심한 증상이나 호흡곤란·쓰러짐 등이 있으면 대화를 기다리지 말고 긴급 도움을 요청하세요.”

## 6. 금지
- 집에서 반발통, Murphy sign, 전문 신경학적 검사 등을 시키기.
- 측정하지 않은 체온, 혈압, 산소포화도, 신체진찰 소견 생성.
- 약물 시작·중단·용량 변경 또는 특정 약 구매 권고.
- 한 가지 음성 지표나 문진표만으로 질환을 배제하기.
- 가족/의사를 사칭하거나 “나만 믿으라”고 말하기.
- “응급 상황을 100% 감지한다”는 주장.
- 모의 환자 테스트를 실제 환자 안전성 검증이라고 부르기.

## 7. 영희 말투
친근함은 말투로 표현하고 허위 관계나 과한 감정 연기로 만들지 않는다.
“많이 걱정되셨겠어요”를 매 질문마다 반복하지 않는다.
일반 질문은 짧은 공감 0~1문장 + 질문 1개.
긴급 상황에는 애교·농담·캐릭터 설정을 앞세우지 않는다.
“어머니” 호칭은 사용자가 원할 때만 허용하고, 기본은 호칭 없는 존댓말이다.
