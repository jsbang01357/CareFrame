# 영희 — 제품 및 구현 명세 v1.0
기준일: 2026-10-09
본 문서의 UX, 우선순위, 시간 제한은 팀의 설계 결정이다. API 기능의 근거는 SOURCES_AND_DISCLOSURE.md에 있다.

## 1. 제품 정의
**아플 때 편하게 말하면, 다음 행동과 진료 준비 자료가 남는 가정용 AI 건강 길잡이.**

장기 비전은 가정의 첫 의료 상담 창구다.
오늘의 시연은 성인이 자기 상복부 불편감을 이야기하는 단일 경로다.
주요 데모 인물은 60대 성인으로 하되, 나이가 많다는 이유만으로 이해력이 낮다고 가정하지 않는다.
의료기관을 대체하거나 건강을 항상 감시하는 제품이 아니다.

### 전달할 한 문장
“대화는 편안하게, 기록은 확인 가능하게.”

### 사용자가 얻는 결과
1. 쉬운 한국어로 자신의 증상을 이야기한다.
2. 확인된 위험 신호가 있으면 문진보다 도움 요청이 먼저다.
3. 그 외에는 의료진에게 전달할 요약과 아직 확인하지 못한 정보가 남는다.

문진표 생성이 실제 진료시간을 단축한다는 주장은 이번 프로젝트에서 입증하지 않는다.

## 2. 범위 고정
| 구분 | 오늘의 범위 |
|---|---|
| 페르소나 | 영희 1명. 성인 여성 느낌의 다정하지만 과장되지 않은 AI |
| 언어 | 한국어 |
| 대상 | 만 18세 이상, 자신의 증상을 직접 이야기하는 사용자 |
| 지원 증상 | 상복부/명치 불편감, 속쓰림에 관한 자체 문진 경로 |
| 입력 | 실시간 음성. 텍스트 수정/입력은 항상 보조 경로로 제공 |
| 출력 | 다음 행동, 확인된 진술, 미확인 정보, A4 인쇄용 문진표 |
| 안전 | 정해둔 위험 신호, 불확실성 표시, 중단/범위 밖 처리 |
| 검증 | 모의 증례 12개 회귀테스트 + 실제 음성 실행 3회 |
| 실행 환경 | 발표 노트북 Chrome 우선. 모바일 반응형, Safari는 시간 내 검증 범위만 표시 |

CPX는 병력 수집 방식을 참고하는 개념이다. 공식 54증례 전체를 구현·검증했다고 말하지 않는다.
확장 가능성을 이유로 53개의 빈 JSON 파일을 만들지 않는다.

### 완전히 제외
복수 페르소나, 얼굴 영상, 음성 복제, 기기 제작, 상시 듣기, 가족 프로필,
과거 세션 기억, 다국어, 영상/신체진찰, 사진 진단, 질환 확률, 약물 추천,
예약/지도/EMR, B2B 관리자 화면, 로그인, 결제, RAG, 외부 병원 검색.

## 3. P0 완료 조건
- 사용자가 시작 버튼을 누르고 마이크를 허용하면 한국어 음성 3턴 이상이 이어진다.
- 수집된 정보가 실제 사용자 전사에 연결된다.
- 사용자가 한 번에 말한 정보를 다시 불필요하게 묻지 않는다.
- 잘못 인식된 문장은 텍스트로 수정할 수 있다.
- not_assessed와 denied가 다른 값으로 유지된다.
- 정해진 위험 증례에서는 다음 일반 질문보다 중단 화면이 먼저다.
- 종료 시 환자 진술 기반 문진표가 브라우저 인쇄로 나온다.
- 최소 12개 회귀테스트의 실제 결과가 파일로 남는다.
- 실제 작동한 버전의 시연 영상과 제출 가능한 링크가 있다.

## 4. UX — 실제 화면 3개
### A. 시작
제목: “어디가 불편하세요? 함께 정리해 볼게요.”
설명: “저는 AI 건강 길잡이 영희예요. 진단이나 처방 대신, 증상을 정리하고 의료진에게 전달할 준비를 도와드려요.”
상시 표시: “가상 증례 시연용 · 현재 성인 상복부 불편감 경로만 지원”
필수 체크:
- AI 및 외부 API로 음성/텍스트가 처리됨을 이해한다.
- 시연에 실제 개인정보나 실제 환자 정보를 입력하지 않는다.
- 성인의 자기 증상을 가정한 시나리오임을 확인한다.

버튼은 “대화 시작” 하나가 중심이다. 마이크 거부 시 “글로 이야기하기”.
나이·성별·이름을 실명 회원 프로필처럼 수집하지 않는다. 가상 인물 설정만 사용할 수 있다.
첫 음성은 “안녕하세요, AI 건강 길잡이 영희예요. 오늘 어디가 가장 불편하세요?”

### B. 대화
왼쪽/모바일 상단: 영희 이름, AI 표시, 현재 질문, 듣는 중/확인 중/말하는 중.
오른쪽/모바일 하단: “지금까지 들은 내용”과 미확인 항목.
하단: 마이크 일시정지, 글로 답하기, 지금까지 정리, 대화 종료.
수집 항목의 원문 버튼을 누르면 해당 발언으로 이동한다.
음성 전사는 “자동 전사 · 수정 가능”으로 표시한다.
가짜 파형·가짜 ‘연결됨’·실제 수집과 관계없는 진행률 금지.

폰트는 일반 본문 18px 이상, 주요 질문 24px 내외를 목표로 한다.
단순한 밝은 배경과 높은 명암 대비. 위험이 없다는 의미의 초록 ‘안전’ 배지는 만들지 않는다.
아바타는 이니셜이나 단순 도형으로 충분하다. 인물 이미지 제작에 시간을 쓰지 않는다.

### C. 결과
가장 위: 다음 행동 / 문진이 완료 또는 중단된 이유.
그 아래: 주호소, 현병력 항목, 동반증상, 약/병력, 사용자 걱정, 미확인 사항.
표기: “사용자 진술을 정리한 사전 문진 자료입니다. 자동 전사 오류가 있을 수 있으며 의료진 확인이 필요합니다.”
“내용 확인 및 수정”과 “의료진용 문진표 인쇄”.
새로고침하면 정보가 지워짐을 안내한다.

긴급 경로에서는 결과보다 경고 화면이 우선이다.
119 안내 버튼은 실제 신고 완료를 의미하지 않는다. 자동 신고 기능은 없다.
노트북에서 전화가 되지 않아도 번호와 행동이 읽혀야 한다.

## 5. 아키텍처 결정
**Next.js + TypeScript + React + 단일 Node 서버 경로**
입력 검증: Zod
음성: @openai/agents/realtime의 RealtimeSession/WebRTC
사실 추출: 서버에서 OpenAI Responses API와 Structured Outputs
테스트: Vitest. 브라우저 테스트 도구는 환경에 이미 있거나 설치가 쉬울 때만 추가.
PDF: 별도 생성 서버 없이 A4 print CSS + 브라우저 인쇄.

기본 경로:
사용자 음성
→ 확정된 전사 이벤트
→ 서버 /api/turn
→ 사실 후보 추출
→ 스키마·근거·주체·시점 검증
→ 결정적 상태 업데이트
→ 안전 규칙
→ 고정 우선순위의 다음 질문 선택
→ 승인 문장을 영희 목소리로 재생
→ 같은 상태를 화면/문진표에 렌더링.

### 가장 중요한 분리
- 모델: 자연어에서 사실 후보를 추출한다.
- 코드: 후보 검증, 질문 선택, 중단, 출력 자료를 결정한다.
- 영희: 승인된 질문을 편안한 말투와 음성으로 전달한다.
- 최종 문진표: 새 LLM이 쓰는 글이 아니라 이미 수집된 상태를 보여주는 템플릿이다.

이 구조 자체가 정확성 보증은 아니다. 전사·추출·문장 재생 단계는 각각 실패할 수 있다.

## 6. 모델 설정
공식 문서 확인 기준의 기본 후보:
| 역할 | 설정 이름 | 기본 후보 |
|---|---|---|
| 실시간 음성 | REALTIME_MODEL | gpt-realtime-2.1 |
| 실시간 입력 전사 | REALTIME_TRANSCRIPTION_MODEL | gpt-live-transcribe |
| 사실 구조화 | EXTRACT_MODEL | gpt-4.1-mini |
| Plan B 파일 전사 | FILE_TRANSCRIPTION_MODEL | gpt-4o-mini-transcribe |
| 고정 안전 안내 음성/Plan B | TTS_MODEL | gpt-4o-mini-tts |

계정 접근 가능 여부는 이 문서에서 확인하지 않았다. 첫 15분에 실제 호출로 확인한다.
기본 후보가 접근 불가하면 공식 문서에 있고 계정에서 호출되는 동급 모델을 한 번만 선택하고 기록한다.
모델 비교 실험이나 임의의 모델명 추측에 시간을 쓰지 않는다.

Realtime-2.1은 공식 모델 문서상 Structured Outputs가 지원되지 않는다.
따라서 Realtime 도구 호출 결과를 strict JSON으로 보장된 임상 사실처럼 취급하지 않는다.
별도의 추출 응답은 SDK의 구조화 출력 도우미와 Zod로 검증한다.
Structured Outputs 역시 내용의 진실성을 보장하지 않는다. [S2–S7]

## 7. 실시간 음성 제어 — 경쟁력을 좌우하는 부분
### 필수 정책
- VAD는 사용하되 자동 응답 생성은 끈다.
- SDK의 createResponse=false / 원시 API의 create_response=false를 설치 버전에 맞게 사용한다.
- 사용자 말 끊기는 지원하되, 새 전사를 처리하기 전 다음 임상 질문은 생성하지 않는다.
- SDK sendMessage 같은 고수준 호출이 응답을 자동 생성하는지 확인한다.
  텍스트 보조 입력도 동일한 서버 검증 경로를 우회하지 않아야 한다.
- 입력 전사는 비동기다. 최종 전사 이벤트를 받기 전에 마지막 발언이 기록됐다고 가정하지 않는다.
- Realtime history가 아니라 InterviewState를 화면·리포트의 유일한 기준으로 쓴다. [S3, S4]

### 한 턴
1. speech started: 재생 중인 응답을 중단하고 현재 음성 세대를 만료시킨다.
2. final transcript: item ID/turn ID로 중복을 제거해 대기열에 넣는다.
3. 한 요청씩 /api/turn으로 전달한다.
4. 응답의 base revision이 현재 상태와 맞는지 확인한다.
5. UI에 새 상태와 다음 질문/중단 안내를 먼저 반영한다.
6. 사용자가 다시 말하는 중이 아니고, 대기 중인 더 새 입력도 없으면 승인 문장만 읽게 한다.
7. 더 새 발언이 있으면 오래된 음성은 재생하지 않고 다음 입력부터 처리한다.

최종 전사의 도착 순서가 발언 순서와 다를 수 있음을 처리한다.
SDK 이벤트 ID/이전 항목 연결을 사용하고, 도착 시각만으로 발언 순서를 단정하지 않는다.

### 안전 분기
서버가 긴급 경로를 반환하면:
- 일반 질문 큐 삭제.
- 진행 중인 Realtime 출력 취소 및 재생 중단.
- 화면 경고 즉시 표시.
- 사전에 만든 고정 안전 음성 클립 재생. 모델에게 안전 안내를 새로 창작시키지 않는다.
- 고정 클립은 행사 중 TTS로 생성하거나 팀원이 읽어 녹음하고 출처/방법을 기록한다.
- 녹음·모델 실패에도 읽을 수 있는 화면 경고는 유지한다.
- 문진표는 그때까지 정보로만 구성한 “긴급 안내로 중단된 자료”다.
- 같은 세션에서 자동으로 비응급 경로로 되돌리지 않는다.
  전사 오류 정정은 기록하되 이미 발생한 경고를 없었던 일로 숨기지 않는다.

일반 질문도 승인 문장 읽기 지시를 사용하지만, 음성 모델이 내용을 바꿀 가능성은 남는다.
실제 출력 전사를 점검하고 예측하지 못한 의학 조언이 나오면 그 버전을 제출용으로 통과시키지 않는다.
방어 기능만으로 의료적으로 안전하다고 주장하지 않는다.

## 8. 성능·실패 처리
- 일반 답변 종료부터 다음 질문 첫 음성까지 중앙값 5초 이내를 UX 목표로 삼는다.
  실제 측정 전 성능으로 주장하지 않는다.
- 8초 이상 처리되면 “말씀하신 내용을 확인하고 있어요”라는 화면 상태와 취소를 제공한다.
- 15초에 해당 턴을 timeout 처리한다. 원문은 보존하고 재시도/텍스트 수정으로 전환한다.
- 형식 오류 자동 재요청은 한 번 이내. 무한 재시도 금지.
- 429/권한 오류는 보여주고 멈춘다. 성공 화면으로 바꾸지 않는다.
- 개발용 mock은 별도 표시하고 평가·시연 결과와 섞지 않는다.
- 사용자 종료·오류·페이지 이탈 시 마이크 트랙과 음성 연결을 닫는다.
- 앱은 백그라운드 건강 모니터가 아니다. 기본 세션 상한은 8분, 무응답 90초면 일시정지한다.
- 일반 문진 응답은 최대 12턴을 작업 상한으로 둔다. 필수 정보가 남으면 ‘미완료’로 종료한다.
  이 상한은 적절한 의료 문진 길이나 충분한 평가를 뜻하지 않는다.

## 9. 저장·보안
메모리 내 InterviewState만 사용한다. 새로고침 시 삭제된다.
서버 route는 요청 단위로 처리한다. DB와 process-global 세션 맵은 없다.
일반 API 키를 NEXT_PUBLIC 변수에 넣지 않는다.
Responses 요청은 store=false. Realtime tracing과 민감정보 로그를 비활성화한다.
이 설정은 공급자의 데이터 보존이 전혀 없다는 뜻이 아니다. [S8]
공개 데모는 가상 정보 전용이며 프로젝트별 API 키와 사용 예산을 사용한다.
입력 크기·턴 수를 제한하고 같은 출처 요청만 받는다. 이것을 완전한 남용 방지라고 홍보하지 않는다.
다중 사용자 서비스용 인증·신뢰 경계는 이번 범위가 아니다.
