# 설계 작업 점검

- CI 빌드 검사에 로컬 `.env.local`을 필수로 요구하지 않는다. CI에는 OpenAI 키를 보내지 않고 환경 파일·키 패턴을 검사하며, 로컬에서는 기존 키 값 대조도 추가한다.
- 정책 변경 후 테스트 기대값을 갱신할 때 검증을 생략하지 않는다. 위험 신호 후 문진 계속과 정정·종료 뒤 응급 안내·근거 유지, 타인 위험을 본인 기록에 합치지 않는 조건을 함께 검사한다.

- 공개 DNS 조회·IP 지정 TLS·특정 브라우저 성공만으로 모든 일반 접속 성공을 선언하지 않는다. macOS DNS 음성 캐시가 남으면 시스템 lookup은 계속 실패할 수 있다. 일반 조회의 실패와 사용자 브라우저 오류를 미해결로 명시한다.

- OpenNext는 서버 환경 파일을 번들에 포함할 수 있다. 실제 키를 제거한 격리 소스에서 빌드하고 완성 번들을 기존 키 값과 대조한다. 키는 승인된 Worker secret으로 별도 등록한다.
- 격리 빌드에 node_modules를 복사할 때 `.bin` symlink를 원문 그대로 보존한다. 경로 재작성이나 외부 symlink는 standalone 추적 누락·중복 React 로딩을 만들 수 있다.
- 프로덕션 빌드와 dry-run 성공만으로 배포 성공을 판단하지 않는다. Next 16.4 preview manifest 수집 누락은 실제 Workers 초기화에서만 실패했으며 실제 도메인의 서버 경로까지 확인해야 발견할 수 있었다.

- 한국어 프로젝트 문서를 작성한 뒤 다른 언어가 섞이지 않았는지 확인한다.
- 전사 모델의 전용 세션 제약과 대화 세션의 설정을 동일하다고 가정하지 않는다.
- 턴 상한과 필수 질문 수를 함께 계산하고, 상한 도달 시 미완료를 명시한다.
- Next Request URL의 hostname이 정규화될 수 있다. 로컬 origin 검사는 실제 Host와 프로토콜도 확인한다.
- 구조화 출력 성공은 의미 정확성의 증거가 아니다. 전 항목 nullable 맵은 미언급 해석을 늘렸고, 실제 진술 후보 배열로 줄인 뒤 회귀 결과가 개선됐다.
- 실제 평가 모델명은 평가 스크립트의 기본값이 아닌 서버 설정에서 읽는다. 기존 .env.local의 모델 지정이 기본값보다 우선한다.
- 정정 검사에서 사흘/3일 같은 동의 표현을 허용하되, 대체 발언의 정확한 원문 근거와 이전 근거 무효화를 함께 검사한다.
- 질문을 표시한 이력과 답변을 얻은 상태는 다르다. 미확인 항목은 표시 이력만으로 건너뛰지 않는다.
- 텍스트 모드에서 마이크 일시정지 메시지를 표시하지 않는다. 입력 실패가 남으면 자료는 미완료로 표시한다.
- 빈 음성 전사는 입력 실패와 구분한다. 잡음으로 생긴 빈 항목은 순서만 확정하고 연결을 유지한다.
- 음성 출력 전사와 재생 완료는 응답 ID로 현재 승인 문장에 연결한다. 늦은 이전 응답 때문에 현재 연결을 닫지 않는다.
- 전사 대기 중 다음 질문을 버리지 않는다. 최신 승인 질문을 보관해 대기 발언 처리 후 재생하고, 선행 항목 도착 시 큐 처리를 다시 시작한다.
- 일반 문진 진행 검증과 범위 확인(`q_scope`) 진행 검증을 구분한다. 이미 범위가 확인된 고정 후보만으로는 사용자가 두 번째 질문에서 멈추는 문제를 검증할 수 없다.
- 짧은 범위 확인 답변은 실제 질문 연결로 해석하고, 모델 추출에는 해당 질문 문구도 전달한다. 다른 질문의 “네”를 지원 범위 근거로 사용하지 않는다.
- 사용자가 반복해서 조기 종료를 보고하면 고정 증례나 추정 원인을 먼저 수정하지 말고 실제 화면의 원문·버전·종료 사유를 확인한다. 음성 종료가 상태 엔진의 의도적 종료인지 먼저 구분한다.
- 공통 문진에서 신체 부위만으로 자동 종료하지 않는다. 질문 상한은 필수 항목 수와 범위 확인·추가 질문 수를 합쳐 검증하고, 스키마·API·엔진의 동일 상수를 사용한다.
- 음성 상태가 `speaking`이어도 첫 인사와 기본 대기는 기본 표정을 유지한다. 후속 질문을 말하는 상태와 첫 인사를 구분한다.
- 문진 상태 종료와 음성 연결 종료를 분리한다. 마지막 안내는 입력을 중단한 뒤 재생하고, 해당 출력의 재생 완료 또는 제한 시간 이후 연결을 닫는다.
- 의료진 편집본은 환자/의료진 화면 전환과 정정 화면보다 상위 상태에 보관한다. 원문 revision이 바뀌면 편집본을 보존하면서 검토 상태를 만료하고 복사·인쇄를 차단한다.
- 실행 필드를 늘릴 때 질문 수·답변 상한·구조화 출력 예산을 함께 확인한다. 추출 실패 원인이 입증되지 않으면 토큰 부족으로 단정하지 않는다.
- 복용약·과거력·수술·알레르기의 “예” 클릭은 이름이나 내용을 제공하지 않는다. 불명확 상태로 기록하고 상세 질문으로 확인한다.
- Realtime의 모든 error를 연결 종료로 처리하지 않는다. `response_cancel_not_active`는 취소 대상 없음이며 공식 문서상 세션에 영향을 주지 않는다. 이 코드만 비치명적으로 처리하고 실제 인증·통신 오류의 종료는 유지한다. 화면의 “음성 연결 꺼짐”과 서버 API 중단은 실제 HTTP 응답으로 구분한다.
- 음성 재생 완료(`stopped`)와 중단(`cleared`) 모두 대기 상태를 해제한다. 중단된 미완료 질문은 빈 전사 후 복구하되 새 질문이 있으면 우선하고, 완료된 질문은 반복하지 않는다. 이전 응답 이벤트의 전역 취소는 최신 승인 문장까지 지울 수 있으므로 응답 ID로 취소하고 새 생성 요청 시 이전 재생 ID를 비운다.
- 전체 대화의 `previous_item_id`를 이전 사용자 전사 ID로 가정하지 않는다. 입력 감지·커밋 순서로 음성 항목을 연결하고, 전사 완료 순서가 뒤집혀도 답변 순서를 유지한다. 짧은 지연만으로 연결을 끊지 않으며, 선행 항목이 풀린 뒤 남은 타이머가 정상 처리 중 실패를 만들지 않게 한다.
- 발언 종료·출력 중단 이벤트 하나에만 재개를 의존하지 않는다. 현재 입력의 커밋·최종 전사와 현재 출력의 취소 완료도 상태를 해제하며, 이전 항목의 늦은 완료는 새 항목을 건드리지 않는다. 음성 연결 실패 뒤 문진 전체를 새로 시작하는 대신 기록을 유지하는 재연결 경로를 제공한다.
- 모델 해석의 근거 불일치와 사용자 입력 실패를 구분한다. 검증 가능한 후보는 유지하고 틀린 범위/사실 후보는 확정하지 않으며, 해석할 수 없는 답변도 원문과 불명확 상태로 저장해 문진을 이어간다. 모델 재시도 때문에 정상 발언 보존이 화면 제한 시간을 넘지 않도록 한다.
