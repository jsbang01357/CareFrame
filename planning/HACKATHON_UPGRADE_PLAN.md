# 해커톤 개선안 · 2026-10-09

## 결정 제안

영희의 제품 설명을 **환자가 말하면, 의사가 확인·수정해 사용할 병력이 준비되는 한국어 음성 사전문진**으로 좁힌다. 환자 대화 → 주호소별 빠진 정보 보충 → 의료진 검토 → EMR 복사까지 하나의 시연으로 완성한다.

이 문서는 현행 코드·화면과 공식 자료를 확인한 개선 제안이다. 아래 기능을 구현하거나 임상 검증한 결과가 아니다. 남은 개발 시간과 현장 최종 심사 안내는 아직 확인되지 않았다.

## 확인한 약점

- CPX 48개 목록은 있지만 선택 주제가 첫 질문·보고서 메타데이터에만 반영된다. `chooseNext`와 추출기는 공통 사전을 사용한다. 증상에 따른 후속 질문 차이가 없다.
- 원문 기반 질문 초안은 가슴통증 78개, 두통 44개, 복통 85개다. 나머지 45개는 질문 골격이며 모든 개별 질문은 비활성이다. 48개 완성형 문진으로 소개할 근거가 없다.
- 보고서의 NRS, 지속시간, 완화 요인, 오심, 수술력, 알레르기, 가족력은 실행 필드에 없다. `requiredFields`에는 증상 양상·식사 관계·과거력도 포함되지 않아, 질문을 끝내도 의사용 노트가 비어 있을 수 있다.
- 발목 증례에도 복부 출혈 등 공통 위험 질문이 이어진다. 현재 가슴 불편감을 보고하면 설정된 규칙이 즉시 중단하므로 가슴통증 전용 경로를 정상 문진으로 단순 연결할 수 없다.
- 현재 의료진 화면은 읽기·원문 이동·복사·인쇄 위주다. 의료진이 내용을 확인하고 보충하는 사용 장면이 없다.
- 시작 화면에서 48개 전문 용어, 문항 출처 상태, 모델 설정 안내가 실제 사용자 과업보다 앞선다. 작은 화면에서는 대화 시작까지 스크롤이 길다.
- 실제 마이크 전체 진행 검증은 남아 있다. 기존 API 회귀 12/12 결과는 개발자가 본 가상 사례이며 독립 임상 평가가 아니다.

## 경쟁 제품에서 확인한 것

[Infermedica Intake](https://infermedica.com/solutions/intake)는 방문 전 동적 문진, 증상 유무·병력 구조화, 의료진 전달, 복사/PDF/API를 제공한다고 설명한다. [Abridge](https://www.abridge.com/product)는 기록과 원자료를 연결하는 Linked Evidence 및 EHR 작업 흐름을 제공한다.

따라서 음성, AI 요약, 원문 링크, PDF 자체를 독점적 차별점으로 발표하지 않는다. 이번 팀이 보여줄 초점은 **한국어 환자 발언의 부정·불확실성·정정을 보존하면서 주호소별 미수집 정보를 채우고, 의료진의 검토까지 연결하는 완성된 흐름**이다. 경쟁사에 이 조합이 없다는 주장은 하지 않는다.

| 순서 | 변경 | 시연에서 보일 결과 | 관련 모듈 |
|---|---|---|---|
| 0 | 실제 음성 전체 진행·정정·종료 재현, 실패 원인 먼저 수정 | 환자가 말한 내용이 끝까지 노트에 남음 | `lib/voice/controller.ts`, `evaluation/voice-checks.md` |

| 2 | 의료진 검토 화면 | 상단에서 CC·핵심 HPI·관련 양성/음성·추가 확인 항목 파악, 우측 원문 확인 | `components/ReportView.tsx`, `lib/report/clinical-note.ts`, 새 의료진 검토 컴포넌트 |

| 4 | 시작 화면 단순화 + 환자/의료진 전환 | 환자는 쉬운 표현으로 주호소를 고르고, 의료진은 기록 업무 화면을 봄 | `app/page.tsx`, `app/ui-overrides.css` |
| 5 | 두통 경로 추가, 평가·발표 정리 | 두 주호소의 질문·출력 차이 및 실제 확인한 수치 제시 | 두통 카탈로그, 경로별 회귀, `evaluation/`, 발표 자료 |

복통부터 완성한다. 가슴통증은 기존 위험 중단 시연에 우선 사용하고, 정상 문진 경로를 열기 전 위험 기준·질문 의미를 검토한다. 85개 질문을 순서대로 읽지 않고, 필수 병력과 조건에 따른 추가 질문을 선정한다. 성별만으로 임신·월경 관련 병력을 추정하지 않는다.

질문·추출·근거 검증·보고서가 같은 필드 사전을 참조하도록 좁은 변경으로 연결한다. 카탈로그의 버전과 활성 상태도 함께 갱신한다. 읽을 문장을 AI가 자유롭게 정하거나 새 의료 판단을 만드는 구조로 바꾸지 않는다.

## 의료진 화면의 핵심

- 상단 요약: 가상 환자 연령/성별, CC, 2–3줄 HPI, 관련 양성·음성 소견.
- 추가 확인: 잘 모름 / 불명확 / 미질문을 구분한다. 확인된 정보와 함께 펼쳐볼 수 있게 한다.
- 원문: 필드 또는 요약 문장 클릭 시 근거 발언을 표시한다. 처음부터 모든 원문을 노트 본문에 반복하지 않는다.
- 정정: 환자의 전사 정정은 기존 엔진을 통해 사실과 노트를 다시 계산한다. 의료진 보충은 환자 발언을 바꾸지 않고 별도 수정 내역으로 유지한다.
- 검토 상태: 환자 확인과 의료진 확인을 별도로 표시한다. 근거 revision이 바뀌면 이전 의료진 확인을 만료한다. 데모에서는 검토자 인증·전자서명 기능으로 설명하지 않는다.
- 출력: 간결한 EMR 텍스트와 근거를 펼쳐보는 화면을 구분한다. 초안 여부·검토 상태·미확인 정보를 복사 결과에도 보존한다.

목표는 10–20초 안에 핵심 정보를 파악하는 화면이다. 실제 의료진 피드백 없이 달성했다고 주장하지 않는다. 같은 브라우저의 역할 전환으로 우선 시연하고, 실제 다른 기기로 전달하는 QR·대기열은 시간 여유가 있을 때만 구현한다. 역할 전환을 실제 EMR 연동이라고 표현하지 않는다.

## 첫 화면 변경 제안

큰 질문 하나: ‘오늘 가장 불편한 곳이 어디인가요?’

환자가 쓰는 표현으로 머리/가슴/배/호흡/그 외 선택을 제공하고 상세 주호소 검색을 보조로 둔다. 부위만으로 주호소를 확정하지 않는다. 나이·성별은 다음 단계에서 받는다. 실제 구현한 경로와 공통 문진 범위는 사용자가 선택할 때 명확히 안내한다. 가상 증례·AI 처리 고지는 보존하고 문항 출처·개발 상태의 상세 목록은 개발 문서/정보 펼치기로 옮긴다.

## 남은 시간에 따른 범위

- **2시간 이하:** 음성 결함 수정, 기존 노트의 의료진 요약 화면, 기존 정정 시연, 첫 화면 정리, 영상 확보. 두 번째 경로·QR·새 서버 저장소는 제외한다.
- **3–5시간:** 복통 필드·조건 질문 연결, 의료진 검토와 수정, 평가까지 우선한다. 두통은 앞선 흐름이 통과한 뒤 판단한다.
- **6시간 이상:** 두통을 추가하고 새 가상 증례와 의료진 사용성 피드백을 확보한다. 마지막 시간은 실제 음성·인쇄·발표·제출 검증에 남긴다.

구현 시간은 계획용 범위이며 보장이 아니다. 여러 기능을 동시에 시작하지 않는다.

## 90초 시연 장면

1. 가상 65세 여성이 복통 주호소 선택 후 ‘사흘 전부터 명치가 쓰리고, 식후 심해져요’라고 말한다.
2. 시작·위치·양상·악화 요인이 채워지고, 이미 답한 질문은 건너뛴다. 다음 미수집 항목 하나를 묻는다.
3. 실제 진행에서 필요한 중간 문진을 수행한다. 편집본이면 생략 구간을 표시한다. ‘혈압약 이름은 몰라요’가 약 없음으로 바뀌지 않는 것을 보인다.
4. ‘사흘이 아니라 3주예요’로 정정하고 원문과 HPI 변경을 함께 보여준다.
5. 의료진 화면으로 전환하여 핵심 병력과 추가 확인 항목을 확인한다. 의료진 수정 후 EMR용 텍스트를 복사한다.
6. 별도 가상 위험 증례에서 일반 문진 중단과 고정 안내를 짧게 보여준다.

발표 중심 문장: **‘환자는 편하게 말하고, 의사는 확인할 병력부터 봅니다. 영희는 진료 전에 그 간격을 채웁니다.’**

## 검증과 공식 심사 연결

[행사 공식 안내](https://codex-community-korea.skysplit.chatgpt.site/hackathon/seoul-2026-10)의 ‘심사 기준’ 탭을 2026-10-09 직접 확인했다. 세부 배점은 추후 안내 상태다. 현장 공지가 우선한다.

| 공식 항목 | 보여줄 증거 |
|---|---|
| 문제 정의와 필요성 | 진료 전 환자 발언을 의사가 사용할 병력으로 옮기는 구체적 업무, 기존 설문·일반 요약과의 차이 |
| AI 판단과 해결 방식 | 자연어에서 복수 사실·부정·불확실성을 추출하고, 코드가 누락/질문/중단을 결정하는 실제 사례 |
| 작동하는 결과물 | 실제 마이크 → 경로별 문진 → 의료진 검토 → 복사/인쇄의 연속 시연 |
| 검증과 개선 | 사용자 보고 음성 실패·조기 종료 원인과 수정, 새 사례의 누락·오인·정정 결과 |
| 사업성 및 도입 가능성 | 성인 외래 사전문진 도입 가설, 의원/병원 도입자와 의료진 사용자 구분, 세션별 실제 API 비용·대기 시간 |
| Codex 활용 과정 | 카탈로그 매핑·회귀·실패 분석에 맡긴 작업과 사람이 검토·수정한 내용 |

측정은 미리 기대값을 정한 새 가상 사례로 한다. 필드/상태 정확도, 근거 없는 기록 수, 미질문을 부정으로 바꾼 수, 정정 후 낡은 정보 잔존, 불필요한 반복 질문, 실제 마이크 성공 여부, API 대기 시간을 각각 보고한다. ‘원문 링크가 있다’는 것은 근거의 의미까지 맞는다는 증거가 아니다.

가능하면 의료진에게 가상 노트를 보여 CC·시작 시점·관련 양성/음성·미확인 정보를 찾게 하고 소요 시간·수정점을 기록한다. 소수 시연 결과를 임상 효과·진료시간 절감으로 확대하지 않는다. 진료시간 절감과 구매 의사는 이후 확인할 가설로 남긴다.

## 이번에는 넣지 않을 기능

새 아바타/다국어/질환 확률/처방/RAG/실제 EMR 연동/새 로그인·DB는 우선순위가 낮다. 48개 제목을 늘리는 작업보다, 환자부터 의료진까지 끝나는 한 경로와 그 검증을 먼저 완성한다.
